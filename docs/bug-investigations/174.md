## Deterministic proof and reporting regression

adapter, bounded fetch and smoke loop. With fixed responses and scaled
130/203 ms request delays, a shared 300 ms deadline fails during round two;
a 600 ms control completes the tool round trip. This reproduces the known
budget interaction while holding model outputs fixed. The different live
runs do not isolate all model nondeterminism or prove every old failure had
that cause.

Public-CLI regressions make a scripted paid attempt remain pending until its
200 ms deadline. They cover missing usage and numeric partial usage: exactly
one attempt starts, and six later paid cases stay skipped. CodeRabbit identified
that numeric usage followed by abort was previously treated as exact despite
`incompleteAttempts=1`; its regression failed with exit 1 after all seven
attempts started. The estimator now treats interrupted attempts as lower bounds,
and that regression passes with one attempt, six skips and exit 3. A last-case
control keeps the timeout exit 1 and records no accounting stop because there
are no further selected cases to block. `spend.stopReason` is now `usage_unknown`,
`spend_cap` or `null`; the legacy `stoppedBySpendCap` flag, `skipped_spend_cap`
outcomes, price gate and existing single-case exit behavior remain compatible.
Existing controls verify price-cap stops, uninterrupted runs, free routes and
unavailable prerequisites. No paid API is needed by these regressions.
