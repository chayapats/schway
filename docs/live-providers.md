# Opt-in live provider smoke checks

This is a **paid/remote opt-in**, not a default Bun test, CI job, or capability eval. Run from the revision you want to test. Each selected provider runs in its own OS subprocess and temporary workspace containing a random sentinel; Schway's real streaming loop must call its `read` tool and return **exactly** the value read. No session is persisted. The parent removes the workspace only after the worker and its process group are proven stopped. The exposed read tool rejects any path except the relative sentinel name (including absolute paths); any unadvertised non-`read` call fails with `failed_provider` / `disallowed_tool` **before any tool executes**. No extensions, interactive login, other filesystem tools or TUI are loaded.

```sh
# One API-key lane. Explicitly opt in before any credential lookup or network call.
ANTHROPIC_API_KEY=... bun run live-smoke --enable-live --provider anthropic
# Other lanes (select exactly the lanes you intend to bill):
bun run live-smoke --enable-live --provider openai-api-key
bun run live-smoke --enable-live --provider compatible --base-url https://example.org/v1 --auth required
bun run live-smoke --enable-live --provider codex
# Local no-key compatible fixture only (no HTTP credentials):
bun run live-smoke --enable-live --provider compatible --base-url http://127.0.0.1:1234/v1 --auth none
# All four only with express operator consent:
bun run live-smoke --enable-live --provider all --base-url https://example.org/v1
# Inspect selection/report shape without looking up credentials or calling providers:
bun run live-smoke --provider all
```

Prerequisites: Bun; for Anthropic `ANTHROPIC_API_KEY` or the Schway OS secure-store Anthropic identity; for native OpenAI `OPENAI_API_KEY` or its own secure-store API-key identity; for compatible an explicit **HTTPS** `--base-url` plus `OPENAI_COMPATIBLE_API_KEY` or endpoint-scoped secure-store key. Plain HTTP is allowed **only** for `localhost`, `127.0.0.1`, or `[::1]` with explicit `--auth none`, never with credentials or on remote endpoints; this is not the default. All selected adapters use a smoke-only fetch policy that rejects redirects (including HTTPS-to-HTTP downgrades) rather than forwarding keys or subscription tokens. `--credential-env NAME`, `--profile NAME`, and `--credential-identity NAME` select the same compatible credential scopes as production. These only apply with `--provider compatible`. Avoid putting keys in arguments, URLs, profiles, or model IDs. The runner does not read `.env` files (`--no-env-file`); export environment values deliberately, or use OS secure storage. Do not put credentials in shell history.

For ChatGPT subscription, sign in **separately** in interactive Schway with `/login codex` (or `/login codex --device` on headless machines) first; the runner uses the same Schway secure-store identity and store-backed automatic token refresh as production. It never opens a browser, requests a device code or silently switches subscription to API-key billing. Expired/revoked sessions needing interaction report `pending` with `subscription_requires_login`. A locked/unavailable OS secure store reports `pending` with `credential_store_unavailable`: unlock or restore store access before retrying, rather than signing in again. Refresh failures unrelated to re-login report `failed_provider`.

Selection: `--provider` accepts `anthropic`, `openai-api-key`, `compatible`, `codex`, `all`, or a comma-separated subset. Use `--model provider=model-id` to override a selected lane (repeat for more than one). By default the built-in model IDs are used; choose tool-capable models. `--timeout-ms N` controls each lane (default 30000, max 120000); exactly two model rounds, 256 requested output tokens per round, a 4096-character budget over streamed text, assembled messages/tool-call arguments and tool results, a cumulative 256 KiB HTTP response-body limit across requests/retries/ordinary subscription refresh before selected adapters parse streams, and Schway's bounded transient retry policy constrain usage. Select **only** providers you intend to contact; a multi-provider invocation runs them sequentially. The installed command has a per-lane deadline including worker startup, followed by a 1500 ms SIGKILL/reap/check **window** for its dedicated POSIX process group; polling, scheduler and filesystem cleanup can add overhead beyond this window. Even if an adapter ignores abort, no later lane launches after a timeout (`prior_run_timeout`). If an output-limit abort leaves a worker unsettled, its framed result is received before exit; after a proven process-group kill and workspace removal it remains `failed_provider` / `output_limit`, never a fabricated timeout. If a worker claims success but leaves a descendant, the supervisor kills the group and reports `failed_runner` / `process_group_leak`, not pass. If stop cannot be certified, it reports `failed_runner` / `process_stop_unverified`, retains the workspace (`cleanup: deferred`) and marks later lanes `prior_run_unsettled`; do not delete that directory until checking for outstanding processes. On Windows the command does **not** launch live workers: it reports `pending` / `supervision_unavailable` because Bun's direct-child kill cannot certify descendants without an OS Job Object. POSIX process-group supervision cannot certify deliberately detached processes escaping that group or a machine failure; do not use executable extensions or external tools in smoke tasks. A streamed tool call may grow before the loop emits a complete message, but the smoke-only fetch wrapper rejects response bytes before adapter SSE parsers consume more than the cumulative ceiling; the assembled-message check still rejects oversized calls before execution. This bounds bytes *delivered to adapters*, not total process memory (a single oversized upstream chunk may be allocated by fetch before the wrapper checks it). Credentials stay in the worker environment/secure store, never subprocess argv, stdin, stdout/stderr, or JSON reports; private stdin carries only selected settings (max 8 KiB), stdout is capped at 8 KiB and raw stderr is discarded. The separately exported `runLiveSmoke` is an **in-process test/programmatic seam**, not a hard-stop API: injected scripted models can bypass the production fetch wrapper, and an uncooperative stream may retain its workspace until settlement. Use the installed CLI for OS-supervised execution.

Report: JSON on stdout with UTC `testedAt`, checked-out Git `revision` (or `unknown` outside a Git checkout), per-lane `provider`, actual `model`, auth source **category** (`env`, `stored`, `stored-subscription`, `none`, `unavailable`), duration milliseconds, `toolRoundTrip`, status and fixed reason code. It never includes a key, raw provider response, endpoint, sentinel, tool output or temp path. Preserve the JSON **with its date/revision/model selection** for live evidence. `passed` means the actual read result was returned verbatim in the final response; `failed_provider` covers transport/model-started timeout/output limit/turn limit/tool-protocol failure; `failed_runner` covers setup/cleanup failure, a hard deadline before the stream starts, or an unverified process stop; `skipped` covers unavailable key/disabled opt-in; `pending` covers unavailable subscription/integration or user cancellation. Aggregate is `passed` (exit 0) only if **all selected** lanes pass; `incomplete` (exit 2) for any skip/pending without failure; `failed` (exit 1) for any failure, including CLI usage errors. Missing credentials are never passed. A fixture result is not live evidence. No paid live run has been performed for this issue.
