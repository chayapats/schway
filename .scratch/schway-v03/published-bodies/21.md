## What to build

Users enable --debug and obtain local diagnostic records that explain model retries, tool failures, compaction and lifecycle transitions without contaminating normal output.

## Existing behavior and problem

The harness already emits normalized run/model/tool/compaction events and redacts known runtime secrets for presentation. There is no opt-in structured diagnostic log. Add one that helps explain failures while leaving headless JSON output and durable session history distinct.

## Prerequisite contract

No blockers. Existing RuntimeEvent is the observation vocabulary; use an internal diagnostic boundary rather than requiring the optional extension observer feature.

## Required behavior and decisions

1. Implement --debug with a documented user-local log location and an optional explicit destination. A disabled logger creates no files and performs no event serialization.

2. Write structured records containing timestamp, level, run/session correlation, component/event and bounded diagnostic fields. Log retries, errors, tool status, compaction transitions and relevant startup/configuration decisions without full conversation dumps by default.

3. Use a shared redaction boundary before serialization: remove credential-bearing structured fields and authorization headers, mask known secret values, and sanitize URL userinfo/query credentials. Error objects must not bypass that boundary.

4. Exclude raw prompts/tool payloads by default because they may contain source/secrets. Include safe identifiers/counts and bounded summaries; do not add a second verbose secret-prone mode in this ticket.

5. Define finite file size/rotation/retention defaults and document them. Serialize writes in order, bound pending memory and make log-write failure nonfatal; a logging error cannot suppress tool settlement or corrupt a session.

6. Keep logs off headless stdout. Normal --json remains the normalized runtime-event stream, while durable JSONL contains only semantic session records.

7. Provide a reusable diagnostic sink for later extension/auth/doctor work without requiring those features to exist. New sensitive fields must go through the same sanitizer rather than hand-built strings.

8. Flush pending bounded records during orderly shutdown/cancellation without hanging indefinitely. No telemetry upload or remote collection is introduced.

## Scope boundary

Local opt-in diagnostics. No telemetry, raw-provider payload logging or persistent transcript archive beyond existing session storage.

## Implementation constraints

- Use Bun and TypeScript. Run `bun run typecheck`; run `bun test` for behavior changes. Deterministic checks use scripted models, protocol fixtures and temporary filesystems rather than paid APIs.
- Schway owns the loop, session engine, context/compaction and tool scheduling. Provider SDKs are protocol clients with automatic retries disabled; core contracts use native conversation types.
- Keep core independent of OpenTUI and provider wire types. Headless execution must not load the TUI; only selected providers and explicitly enabled executable extensions load.
- Resolve tool-relative paths from the canonical primary workspace root (nearest Git root, otherwise launch cwd). Keep runtime events separate from durable semantic session records.
- Document newly exported functions/types with a one-line TSDoc contract. Preserve bounded model-facing output, exactly one result per accepted call and existing credential redaction.

## Verification scenarios

| Scenario | Observable result |
| --- | --- |
| Opt-in | No files when disabled; enabled run emits correlated structured records. |
| Redaction | Injected keys/tokens/header casing/URL credentials/nested errors do not appear in files. |
| Output separation | Headless stdout remains parseable runtime JSONL and sessions contain no log records. |
| Resource failure | Unwritable destination/rotation/write rejection leaves the coding run and tool results intact. |
| Bounds/shutdown | Oversized fields, rotation, bounded buffering and cancellation flush have deterministic tests. |
