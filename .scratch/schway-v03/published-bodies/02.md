## What to build

Bring existing exported functions and types into compliance with the repository's required one-line contract TSDoc, making the existing public seams understandable before extension work.

## Existing behavior and problem

The repository requires a one-line TSDoc contract on exported functions and types. The baseline has clear omissions: canonical conversation content/message types, Workspace, workspace and Git-root resolvers, credential result/source types, and the redaction function. This is a standards correction, not a proposal to replace these types.

## Prerequisite contract

No blockers. Existing implementation is the source of truth; the complete requirement is stated here.

## Required behavior and decisions

1. Inventory exported function declarations, exported callable values, interfaces, type aliases and classes in first-party runtime code. Include exported methods when they expose public behavior and currently lack a contract.

2. Write a concise opening sentence explaining what the caller can rely on: inputs/outputs, side effects, path origin, error behavior or invariants where relevant. 'The Workspace interface' or a restatement of an identifier is insufficient.

3. Describe current behavior from implementation and tests. For example, workspace discovery canonicalizes paths and selects the nearest Git root; secret redaction masks supplied known values rather than guaranteeing arbitrary secret detection.

4. Retain useful existing detailed documentation after the opening contract sentence. Document opaque provider metadata without turning provider-specific fields into the canonical model.

5. Correct stale claims encountered in the edited contracts, especially descriptions that imply parallel scheduling is still a future capability. Do not change runtime behavior to match an aspirational comment.

6. Keep the patch focused on documentation and provide the export inventory with completion evidence in the implementation report.

## Scope boundary

Documentation of existing public contracts. No renames, type redesign, new framework or comment-enforcement dependency.

## Implementation constraints

- Use Bun and TypeScript. Run `bun run typecheck`; run `bun test` for behavior changes. Deterministic checks use scripted models, protocol fixtures and temporary filesystems rather than paid APIs.
- Schway owns the loop, session engine, context/compaction and tool scheduling. Provider SDKs are protocol clients with automatic retries disabled; core contracts use native conversation types.
- Keep core independent of OpenTUI and provider wire types. Headless execution must not load the TUI; only selected providers and explicitly enabled executable extensions load.
- Resolve tool-relative paths from the canonical primary workspace root (nearest Git root, otherwise launch cwd). Keep runtime events separate from durable semantic session records.
- Document newly exported functions/types with a one-line TSDoc contract. Preserve bounded model-facing output, exactly one result per accepted call and existing credential redaction.
